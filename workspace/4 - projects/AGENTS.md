# Workspace: Projects

## Purpose
This folder holds bounded initiatives with clear scope, outcome, ownership, or timeline.

## Inheritance
- Inherit all root and workspace-layer rules automatically.

## Rules
- Each direct child folder in `projects` should represent one real project.
- Each real project should eventually have its own `AGENTS.md` and `MEMORY.md`.
- Do not use portfolio buckets such as acquisition, delivery, or optimization here.
- Do not mix recurring BAU operations here unless the work is a temporary improvement initiative.

## Routing
- Create a direct project folder when the work has a clear beginning, end, deliverable, or owner.
- Keep subfolders inside the project when the structure is specific to that project, such as pages, automations, assets, or funnels.
